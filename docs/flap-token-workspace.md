# Flap token details and execution

The BNB workspace builds OHLC candles from its own indexed Portal trades, following the original Rushr event-to-trades-to-candles pipeline. Native-BNB and ERC20-quoted curves use a cached, indicative quote-asset/USD display price from the deepest matching BSC base-token pair returned by DexScreener. ERC20 decimals and symbols are read from BSC; raw trade amounts use the actual quote decimals, while Portal postPrice uses fixed 18-decimal quote/token units. Historical chart values are converted at that current rate and labelled accordingly; they are not historical USD oracle observations and never authorize a trade. Assets without a valid quote remain unpriced. Curve trading supports native and ERC20 quote assets as described below.

Metadata accepts root CIDs, ipfs:// references and /ipfs/CID gateway URLs, validates the extracted CID and fetches only through the fixed Flap IPFS gateway. It never fetches an arbitrary metadata host.

IPFS metadata is fetched separately by `apps/indexer/scripts/flap-metadata.ts --follow`, with CID validation, a fixed gateway, document limits, and retry cooldowns. Migration 0017 stores sanitized images, descriptions and social links. User-authored descriptions remain untrusted content. Empty metadata is not replaced with invented descriptions.

Migrations 0018-0020 and `flap-holders.ts --follow` provide automatic feed enrollment, bounded transfer replay and finalized holder snapshots with a supply-completeness proof. Distribution includes protocol contracts; concentration excludes them. Coverage-aware classifications are described in `flap-safety.md`. Source-code verification, renunciation and universal honeypot verdicts remain unknown unless actually established.

`packages/trade/src/bsc/flap.ts` implements native-BNB and ERC20-quoted curve quotes, transaction building, exact/reset approvals, stateful simulation and wallet-confirmed execution against the allowlisted BNB Portal. It verifies chain, version, status, supported extensions, NFT ownership, buy caps, decimals, canonical quote blocks, freshness, real balances, net wallet deltas and gas budgets. It rechecks after approvals, never raises slippage or resends failed submissions, and verifies canonical transaction identity and one matching Portal fill before reporting a result. Receipts stay wallet-local; platform ranking ingestion for Flap is not yet connected.

Scope: EOA wallets, native-BNB and ERC20-quoted Flap curves, and the existing verified PancakeSwap v2/v3 spot adapter. A BNB buy on an ERC20-quoted curve uses Portal's internal conversion only when `nativeToQuoteSwapEnabled` is true. Direct quote-asset buys approve only the exact input amount (with a zero reset if required). Sells receive the curve quote token; its address, symbol and actual decimals are pinned in the reviewed quote. The UI offers BNB/quote payment selection, asset-aware USD budgets and balances, and shows the real sell output currency. Delegated/contract wallets and unsupported migration protocols remain outside this adapter. Portal calldata does not contain a deadline: freshness is checked before the wallet request, while minimum output is enforced on-chain. A wallet confirmation delayed beyond the displayed quote expiry cannot be recalled by the app.

For native-hop buys, Portal `eth`/`fee` events are denominated in the intermediate quote token, not BNB. Actual native spend therefore remains null in receipt accounting; local activity shows the reviewed BNB maximum rather than inventing a spend from those event amounts. Direct ERC20 settlement uses actual wallet Transfer deltas. Historical local BNB activity remains compatible.

Read-only rehearsal: run `packages/trade/scripts/rehearse-flap.ts` with the local RPC environment. It has no wallet client or broadcast methods. Browser verification used a read-only provider that rejects every signing/send method, successfully obtained a real quote and simulation, and reached an enabled wallet-confirmation control. No funded transaction was broadcast by the agent.
